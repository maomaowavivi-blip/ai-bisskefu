# v3.31 知识库富文本编辑器本地化 + 后台页面禁缓存 — 蓝图

> 2026-11-19 起草。状态：已审计（锚点均实测）。授权：苏鸣 2026-11-19 明确授权。

## 1. 问题（实测定位）

同事电脑打开生产后台 `https://43.138.217.6/admin/knowledge.html` 编辑知识库条目，**没有富文本编辑器**。

三个叠加原因：

| # | 原因 | 证据 |
|---|---|---|
| 1 | 编辑器 **wangEditor 4.7.15 从 `cdn.jsdelivr.net` 外链加载**，同事网络拉不到 | `admin/knowledge.html:502`；本机与生产服务器 curl 该 URL 均 200，同事网络不通 |
| 2 | 加载失败后 `new E('#editorContainer')` 抛 `TypeError: E is not a constructor`，**该行之后全部脚本中断**（openModal/editEntry/saveEntry 包装都没装上） | `admin/knowledge.html:504-534` |
| 3 | 生产 HTML **无 Cache-Control 头**（只有 Last-Modified/ETag），浏览器启发式缓存数天~数周 → 同事看到的是**旧版页面**（旧版标准答案是带 placeholder="支持富文本" 的 textarea，与当前空 div + hidden input 结构不符） | `curl -I` 实测无 cache 头；截图框内灰字与当前代码结构矛盾 |

附带死引用：`admin/knowledge.html:11` 的 `wangEditor.min.css` **本身 404**（wangEditor v4 的 npm 包内无任何 CSS 文件，样式由 JS 内部 `createElement("style")` 注入）→ 无害但多余。

## 2. 方案

### 2.1 本地化 wangEditor

- 下载 `wangeditor@4.7.15/dist/wangEditor.min.js`（262,438 字节，样式自包含，无外部字体/图片依赖，已实测）
  → `admin/vendor/wangeditor/wangEditor.min.js`
- `admin/knowledge.html:502` 改为 `<script src="vendor/wangeditor/wangEditor.min.js?v=1"></script>`（version query 防缓存）
- 删除第 11 行 404 的 CSS 引用
- **外部依赖归零**：该页不再请求任何外网资源（Google Fonts 字体降级不影响功能，本次不动）

### 2.2 加载失败兜底（不再让整页脚本崩）

`window.wangEditor` 缺失时：
- 不再 `new E(...)`（避免 TypeError 连带整页中断）
- `#editorContainer` 注入一个普通 `<textarea id="kbFallbackText">`，提示「富文本编辑器不可用，已降级为纯文本」
- openModal / editEntry / saveEntry 三个包装**双路径**：有 kbEditor 走富文本；无则走 textarea，保存仍能写回 `#editAnswer`

### 2.3 后台页面禁缓存（nginx）

`/etc/nginx/conf.d/aibisskefu.conf` 新增：

```nginx
    # v3.31：后台页面禁用启发式缓存
    location ~ ^/admin/.*\.html$ {
        add_header Cache-Control "no-cache, no-store, must-revalidate" always;
        add_header Strict-Transport-Security "max-age=31536000" always;
        add_header X-Content-Type-Options "nosniff" always;
        add_header X-Frame-Options "SAMEWORK" always;   # ← 见 §3 注意
        ...
    }
```

⚠️ **nginx add_header 覆盖规则**：子 location 一旦出现 add_header，父 server 级的全部 add_header 会被**整体覆盖**。故新 location 必须**重复声明** server 级的 5 个安全头，不能只写 Cache-Control。

`X-Frame-Options` 沿用 server 级的 `SAMEORIGIN`（写错会丢安全头）。

仅作用于 `/admin/*.html`，不动 C 端 H5 页面缓存策略。

## 3. 影响面与回滚

| 项 | 影响 |
|---|---|
| 后台页面 | 每次打开回源（低频，负载可忽略）；**好处**：以后改后台不必再让人手动刷新 |
| C 端 H5 | 不受影响 |
| 富文本功能 | 行为不变；只是资源来源从公网 CDN 变本地 |
| 回滚 | `git revert` + scp 覆盖 + nginx 恢复备份 + `nginx -t` + reload |

## 4. 验收标准

1. `admin/vendor/wangeditor/wangEditor.min.js` 存在，md5 与官方 npm 包一致
2. 页面源码不再含 `cdn.jsdelivr.net`
3. 生产 `curl -I /admin/knowledge.html` 返回 `Cache-Control: no-cache...`，且 HSTS/nosniff/X-Frame-Options 等安全头**一个不少**
4. `nginx -t` 通过，reload 后站点正常
5. **浏览器实测**（用浏览器工具打开生产页）：编辑器工具栏出现、能输入、能保存；断网/模拟 JS 加载失败时降级 textarea 出现且保存不报错
6. 旧缓存用户硬刷新一次后拿到新版

## 5. 不做

- 不本地化 Google Fonts（C 端体积大，后台用系统字体即可）
- 不改其它 admin 页面的逻辑（dashboard/chat-logs 等无外部依赖）
- 不改 wangEditor 版本（4.7.15 保持原样，避免行为漂移）
