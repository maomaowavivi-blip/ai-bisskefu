**日期**：2026-08-15

## 一、上线判断与验收门槛

当前结论是 **NO-GO**。完成下列 Gate A 后，才允许发放封闭内测入口；Gate B 应在同一维修版本内完成，最迟不得晚于扩大内测。

### Gate A：必须先完成

1. 公网无法下载日志、SQL、源码备份、点文件和运维目录。
2. 客户可控字段不能在客户页或管理后台触发 HTML/JavaScript。
3. `embedding.php`、`sidecar.php` 未登录请求全部拒绝。
4. 已泄露的 VPS、宿家接口凭据完成轮换，仓库当前版本不再包含有效凭据。
5. 已废弃的人工接管入口不再轮询、不再产生 500。

### Gate B：内测稳定性要求

1. 微信消息发送失败不会在保存游标后永久丢失。
2. 主库和 Sidecar 均有可恢复的每日备份。
3. 登录有限流，JWT 不再放入 URL，CORS 不再为 `*`。
4. 短信 Mock 不再对外显示“发送成功”，验证码不再写日志。
5. 安全回归脚本、核心业务回归和部署 MD5 校验全部通过。

## 三、维修包 A：公网暴露紧急收口

### A1. Nginx 禁止访问非公开资产

**生产文件**：`/etc/nginx/conf.d/aibisskefu.conf`

在 HTTPS `server` 中增加以下规则，放在通用 `location /` 和 PHP 规则之前：

```nginx
# 运行状态、SQL、测试和内部文档不属于 Web 资产
location ^~ /logs/    { return 404; }
location ^~ /sql/     { return 404; }
location ^~ /scripts/ { return 404; }
location ^~ /tests/   { return 404; }
location ^~ /docs/    { return 404; }
location ^~ /templates/ { return 404; }
location ^~ /.trae/   { return 404; }
location ^~ /.cursor/ { return 404; }
location ^~ /.claude/ { return 404; }

# 点文件、macOS AppleDouble、备份源码
location ~ (^|/)\._  { return 404; }
location ~ (^|/)\.(?!well-known(?:/|$)) { return 404; }
location ~* (\.bak(?:\.|$)|\.before-[^/]*$|\.(sql|log|md|csv|ya?ml|ini|conf)$) { return 404; }
```

补充响应头：

```nginx
server_tokens off;
add_header Strict-Transport-Security "max-age=31536000" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "no-referrer" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
```

**本版本不直接启用严格 CSP**：后台大量使用内联脚本，贸然加阻断型 CSP 会导致后台不可用。先消除实际 XSS，再单独迁移内联脚本。

### A2. 处理已经暴露的文件

1. 先把 `logs/`、`*.bak*`、`*.before-*`、`._*` 复制归档到 Web 根目录之外的精确目录，例如 `/root/aibisskefu-private-archive/20260815/`。
2. 归档目录权限设为 `700`，文件为 `600`。
3. 归档成功并核对文件数量后，只把 `wecom_kf.log` 截断为新日志，并清理非运行备份、AppleDouble；不得清空整个 `logs/`。
4. `roomcard_thumb_media_id.txt`、微信 cursor 和 msgid cache 是在线运行状态，保持原路径和内容，不移动、不删除。以后若迁移私有目录，必须先改代码路径并做原子复制。
5. 三个“不能删除”的人工接管文件不移动、不删除。
6. 新日志不得记录客户原文、完整外部联系人 ID、游标、消息 ID 或接口响应全文；客户标识只记录不可逆短哈希。

### A3. 日志轮转

新增系统级 logrotate 配置，仅针对新的应用日志：每日轮转、保留 14 天、压缩、权限 `640 apache:apache`。轮转后以一次真实微信消息验证 PHP 仍可继续写入。

## 四、维修包 B：存储型 XSS 与输入边界

### B1. 服务端限制客户可控标识

**文件**：`api/chat.php`、`api/ChatPipeline.php`、`api/openapi.php`

规则：

- `session_id`：`^[A-Za-z0-9_.:-]{1,128}$`
- `visitor_hash`：为空或 `^[A-Za-z0-9_.:-]{1,128}$`
- `channel`：只允许代码定义的固定枚举，不接受任意字符串。
- `message`：限制 UTF-8、最大 2000 字；数据库保存原始文本，但所有展示必须按文本渲染。
- `X-Forwarded-For` 不再直接信任；当前直连 Nginx 使用 `REMOTE_ADDR`。以后接入可信代理时再配置 Nginx `real_ip` 白名单。

校验失败统一返回 400，不写聊天日志。

### B2. 客户聊天页不再用 `innerHTML` 渲染文本

**文件**：`chat.html`

1. `appendMessage()` 使用 `textContent` 创建消息文本和时间节点。
2. 人设 `description/greeting` 使用 `textContent`。
3. 富内容卡片使用 DOM API 创建，标题、地址、房号全部用 `textContent`。
4. 图片和链接仅允许 `https:`；不允许 `javascript:`、`data:text/html`。
5. 保留 `white-space: pre-wrap`，保证换行显示，不依赖 HTML。

### B3. 后台聊天记录全面文本化

**文件**：`admin/chat-logs.html`

1. 会话列表和详情全部使用 DOM API、`textContent`、`dataset` 和 `addEventListener`。
2. 禁止把 `session_id`、消息、设备标识、IP 拼入 `innerHTML`、内联 `onclick` 或 HTML 属性字符串。
3. 使用带恶意标签、引号和事件属性的测试内容验证页面只显示文本。

### B4. 知识库和人设按纯文本处理

**文件**：`api/knowledge.php`、`admin/knowledge.html`、`api/persona.php`、`admin/persona.html`

1. 知识答案保存和 CSV 导入统一 `strip_tags`，以纯文本存储。
2. 列表预览用 `textContent`；编辑器读取时不执行存量 HTML。
3. 人设接口保存时剥离标签，管理页和客户页全部按纯文本展示。
4. 不引入自制 HTML 白名单清洗器。

生产和本地实测均为 149 条知识，包含 HTML 标签的答案为 0；人设 HTML 字段也为 0，因此纯文本化不会损失现有格式。

## 五、维修包 C：接口认证与成本保护

### C1. Embedding 调度器统一管理员认证

**文件**：`api/embedding.php`、`api/knowledge.php`、`api/openapi.php`

不能只在 `embedding.php` 顶部机械加入 `adminGuard()`，否则会打断内部调用。正确改法：

1. 把单条向量化、批量向量化、语义搜索整理为可直接调用的 PHP 函数。
2. 只有当 `embedding.php` 作为 HTTP 入口执行时调用 `adminGuard()`。
3. `knowledge.php` 直接调用向量化函数，不再通过 `HTTP_HOST` 自请求。
4. `openapi.php` 在通过 OpenAPI Key 验证后直接调用 `kbSemanticSearch()`，不再访问公开搜索 URL。
5. 外部直接请求 `vectorize/batch_vectorize/search` 均要求管理员 Bearer Token。
6. 对每次批量向量化保留最多 10 条的现有上限。

### C2. Sidecar 运维接口全部管理员化

**文件**：`api/sidecar.php`、`admin/settings.html`

1. `stats/rebuild_chunks/vectorize_pending/query_room` 全部要求 `adminGuard()`。
2. 设置页 `stats` 请求补上 `getHeaders()`，避免保护后后台统计失效。
3. 删除 HTTP 入口对用户传入 `is_verified` 的信任；核心聊天仍通过 `RoomQueryFlow → RoomQueryService` 进程内调用，并由订单会话状态决定权限。
4. 验证未登录请求全部返回 401，而不是 200、400 或 500。

### C3. JWT、登录与 CORS

**文件**：`api/config.php`、`api/auth.php`、`admin/auth-guard.js`、`api/ChatPipeline.php`

1. `authToken()` 只接受 `Authorization: Bearer`，删除 `?token=` 回退。
2. JWT 签名使用 `hash_equals()`。
3. `auth-guard.js` 的 `/auth.php?action=me` 改为 Authorization Header。
4. 登录失败按 `REMOTE_ADDR + username hash` 使用现有 `rate_limits` 表限制：15 分钟最多 5 次，成功后清除登录键。
5. 聊天限流不再接受任意 `X-Forwarded-For`。
6. 移除全局 `Access-Control-Allow-Origin: *`。当前后台、聊天页和 iframe 都是同源；OpenAPI 是服务端调用，不依赖浏览器 CORS。
7. 如果未来必须跨域，改为显式域名白名单，不允许通配符。

## 七、维修包 E：微信消息不丢失

**文件**：`api/wecom_kf.php`、`api/wecom_kf_dedup.php`

### E1. 调整成功顺序

当前错误顺序是“保存游标/标记消息 → 处理 → 发送”。改为：

1. `syncMsg()` 只返回 `msg_list + next_cursor`，不写游标文件。
2. 已成功处理过的 `msgid` 可跳过并视为成功。
3. 新消息完成 Pipeline 且文本/小程序卡片实际发送成功后，才 `markMsgProcessed()`。
4. 任一待回复消息失败，则本批次不推进游标；成功消息通过去重避免重复发送。
5. 整批成功后才以 `LOCK_EX` 保存 `next_cursor`。
6. 去重有效期由 5 分钟调整为 24 小时，并在写入前清理过期项。
7. 发送失败允许一次短间隔重试；仍失败则保留游标并记录错误码，不记录客户 ID 和消息内容。

### E2. 房卡分支统一成功判定

订单消息仅在以下任一动作成功后标记完成：

- 原生小程序卡片发送成功；或
- 房卡失败提示文本发送成功。

`$roomCardSent` 成功后不能直接 `continue` 而遗漏去重成功标记。

- Nginx：保留修改前配置副本，`nginx -t` 失败立即恢复，不 reload 错误配置。

- 凭据：旧凭据一旦判定泄露不得恢复；回滚只能使用另一组新凭据。
- 微信游标：改动前备份 cursor/cache；出现重复发送时停止回调处理并恢复代码，不手工猜游标。
