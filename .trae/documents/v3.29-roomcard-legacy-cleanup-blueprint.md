## 三、改动清单

### 3.1 `api/wecom_kf_roomcard_v37.php` 删除

- 8 个旧函数(上表)
- `buildRoomCardDeliveries()` 里的**回退分支**(中台失败时回旧宿家)
- 文件头注释中"旧宿家接口,回退用,保留"一行
- 硬编码的 `https://apicenter.sujia365.com/...` 随旧函数一并消失

### 3.2 删除后保留的代码

| 保留 | 说明 |
|---|---|
| `roomCardApiUrl()` / `fetchCenterRoomCards()` / `parseCenterRoomCard()` | 中台房卡链路 |
| `uploadImageToWeCom()` / `getThumbMediaIdCached()` / `forceRefreshThumbCache()` | 企微封面缩略图(含 60h 自愈 + 40007 重发) |
| `buildRoomCardDeliveries()` | 唯一主入口,签名不变 → `api/wecom_kf.php` **零改动** |
| `ROOMCARD_THUMB_URL` / `ROOMCARD_CENTER_API_URL` | 封面图 / 中台端点默认值 |

### 3.3 DB(生产 + 本地同步删)

```sql
DELETE FROM platform_config WHERE `key` IN ('roomcard.username','roomcard.password');
```

- 删除前把两行的值备份到 `/root/aibisskefu-private-archive/<日期>-roomcard-legacy-credentials/`
- **保留**:`roomcard.api_url` / `ai.roomcard.thumb_media_id` / `ai.miniprogram.*`
- 无表结构变更

## 四、后果与降级

清理后**没有回退路径**:中台接口不可用时房卡发不出。
降级行为(`api/wecom_kf.php:419`)已存在,不会崩、不会发旧卡:

```
'暂时没有查找到您的云房卡,请稍后重试或联系管家。'
```

即中台故障 = 客户收到这句文字提示,随后走正常问答流程。
