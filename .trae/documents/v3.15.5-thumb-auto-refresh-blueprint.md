## 一、根因(8/18 17:25 实测确认)

### 现象

客户发订单号 → 客服不再发云房卡 → 客户看到兜底文案:
> "暂时未能打开您的云房卡,请稍后重试或联系前台。"

### 抓根因过程

1. `wecom_kf.log` 显示错误码:
   ```
   [2026-08-18 09:18:14] [wecom_kf] send_kf_mini error: errcode=40007
   ```
   (UTC 9:18 = 北京时间 17:18)

2. 直接调企微 `/cgi-bin/kf/send_msg` 拿完整 errmsg:
   ```json
   {"errcode":40007,"errmsg":"invalid media_id", ...}
   ```

3. 验证 thumb_media_id 缓存:
   ```
   文件: /www/wwwroot/aibisskefu/logs/roomcard_thumb_media_id.txt
   创建时间: Aug 14 20:43 (CST)
   当前时间: Aug 18 17:25
   差距: 3 天 21 小时 = 93 小时
   ```

### 根因

**`api/wecom_kf_roomcard_v37.php:204` 注释里写着**:
```php
/**
 * 获取缩略图 media_id(文件缓存,首次上传后永久使用)
 */
```

—— "**永久使用**"是 bug。

`buildRoomCardDelivery()` 第 266 行永远从 DB 缓存 `ai.roomcard.thumb_media_id` 读 thumb,没设置任何过期检测。**企微临时素材有效期 3 天**(实测 72 小时左右),8/14 上传 → 8/17 20:43 失效 → 8/18 9:18 第一次发卡失败。

### 历史经验

v3.15.2 时代(v3.14 之前)已经多次踩这个坑,改过 B 样式 → A 样式切换。但**根本问题**(thumb 不自动刷新)**从未修过**。

## 二、方案

### 2.1 缓存文件加时间戳(主方案)

把 `roomcard_thumb_media_id.txt` 内容从单行 `media_id` 改为 JSON:
```json
{"media_id": "3W2la-FkeG...", "created_at": 1787045216, "expires_at": 1787045216 + 60*3600}
```

`getThumbMediaIdCached()` 新逻辑:

```php
function getThumbMediaIdCached(): ?string {
    $cacheFile = __DIR__ . '/../logs/roomcard_thumb_media_id.txt';
    
    if (file_exists($cacheFile)) {
        $raw = trim(file_get_contents($cacheFile));
        // 兼容旧格式(只有 media_id 一行)
        $decoded = json_decode($raw, true);
        if (is_array($decoded) && isset($decoded['media_id'], $decoded['created_at'])) {
            // 60 小时内复用(留 12 小时缓冲,72 - 60 = 12)
            if (time() < $decoded['created_at'] + 60 * 3600) {
                return $decoded['media_id'];
            }
            // 过期 → 删除,走重新上传路径
            @unlink($cacheFile);
        } elseif (preg_match('/^[A-Za-z0-9_-]+$/', $raw)) {
            // 旧格式(只有 media_id):直接当成过期,删了重新上传
            // 保留向后兼容 1 次,后续稳定
            @unlink($cacheFile);
        }
    }
    
    // 重新上传
    $token = getAccessToken();
    if (!$token) return null;
    $mediaId = uploadImageToWeCom($token, ROOMCARD_THUMB_URL);
    if ($mediaId) {
        @file_put_contents($cacheFile, json_encode([
            'media_id'   => $mediaId,
            'created_at' => time(),
        ]));
    }
    return $mediaId;
}
```

### 2.2 同时刷新 DB 缓存(必须)

`buildRoomCardDelivery()` 第 266 行也从 DB 读 thumb:
```php
$thumb = trim((string)pcGet($db, 'ai.roomcard.thumb_media_id', ''));
```

也要一并刷新,否则文件缓存新了但 DB 还是老的,下次 buildRoomCardDelivery 还是会用老的:
```php
// buildRoomCardDelivery() 末尾
$parsed['thumb_media_id'] = $thumb;
// v3.15.5:同步写回 DB(下次 buildRoomCardDelivery 直接读)
pcSet($db, 'ai.roomcard.thumb_media_id', $thumb);
```

(每次发卡都写 DB 一次,确保两边同步)

### 2.3 不动的地方

- `uploadImageToWeCom()` — 完全不动
- `buildRoomCardDelivery()` 整体逻辑(只是最后多一行 pcSet)
- ChatPipeline / IntentRouter / OrderQueryWorkflow — 全部不动

## 三、风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 旧缓存格式兼容性 | 低 | 保留"只匹配 media_id 的旧格式"分支,首次执行删旧缓存走新上传 |
| 60 小时阈值选错 | 低 | 企微临时素材实际有效期约 72 小时(已实测),60 小时留 12 小时缓冲。如果某次企微调整有效期,可以调这个数 |
| DB 写入失败(权限/锁) | 极低 | pcSet 内部有 try/catch,失败不影响本次发卡 |
| 频繁重新上传消耗企微配额 | 低 | 60 小时阈值 = 每天最多重新上传 ~0.4 次,可忽略 |
| getThumbMediaIdCached 抛异常 | 极低 | 调用方已 try/catch,返 null 走兜底文案 |

## 四、改动前后对比

| 场景 | 旧 | 新 |
|---|---|---|
| 首次发卡 | 上传 thumb,文件缓存 | 上传 thumb,文件缓存(带 timestamp) |
| 3 天内再次发卡 | 用文件缓存 | 文件缓存 < 60 小时,直接复用 |
| **3 天后再次发卡** | ❌ 拿旧 thumb → 40007 invalid media_id → 兜底文案 | ✅ 缓存过期自动重新上传,新 thumb 生效 |
| 旧格式缓存(只有 media_id) | 读旧 thumb,直接发,40007 | 兼容:识别旧格式,删掉重新上传 |
