# v3.13 云房卡直接使用宿家 urlLink 蓝图

## 1. 目标

修复云房卡卡片标题取错字段及点击后空白：

- 标题从宿家 `shareText` 中提取面向客户展示的真实房间号，格式为“您的房间为 房间号”。
- 微信客服直接发送 `link` 卡片，链接原样使用宿家 `share_bundle.miniapps[0].urlLink`。
- 不再优先发送第三方小程序 `appid + path`，避免企微显示发送成功但客户打开空白。
- 封面继续使用当前固定封面素材。

## 2. 真实审计结论

2026-08-15 使用用户指定测试订单进行只读复现：

1. `baoyu_room_no` 是宿家房卡内部/测试编号，不是客户文案中的真实房间号。
2. `shareText` 的 `【房源名称的房间号号房间】` 结构包含客户实际应看到的房间号。
3. `miniapps[0].path` 参数本身完整，且与 `encryptedId` 一致，但企微原生小程序卡片打开后为空白。
4. `miniapps[0].urlLink` 符合 `weixin://dl/business/?t=...`，旧版 link 卡片在线上已有成功发送记录。

因此问题不是订单参数缺失，而是选择了不适合当前企微场景的原生小程序发送方式。

## 3. 实现

### 3.1 标题

新增房间号提取规则：

1. 优先从 `shareText` 的中文书名括号 `【...】` 中取房源描述。
2. 删除最后一个“的”以前的房源名称。
3. 删除结尾“号房间”。
4. 标题生成：“您的房间为 ” + 提取结果。
5. 无法提取时才回退 `baoyu_room_no`，最后回退“宿家云房卡”。

### 3.2 跳转

订单号处理流程改为：

1. 查询/必要时生成房卡。
2. 解析宿家完整 `urlLink`。
3. 直接调用 `sendKfLinkMessage()`。
4. 发送失败才返回文字提示，不再回退到会打开空白的原生小程序卡片。
