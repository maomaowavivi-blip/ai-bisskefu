# v3.15.2 A 样式云房卡回归修复蓝图

**日期**：2026-08-15
**目标**：恢复优化前已经可打开的 A 样式原生小程序卡片。

## 一、以真实回归结果为准

用户确认：v3.15 安全优化前，A 样式云房卡可以正常打开。因此本次不改变宿家返回的 `appid`、`path`、订单参数，也不把 A 改成 B。

对比 v3.14 与 v3.15 代码后确认：

1. v3.14 的 A 卡片载荷使用宿家返回的 `appid`、`path` 映射的 `pagepath`、标题和缩略图。
2. `api/wecom_kf_roomcard_v37.php` 在 v3.15 前后没有变化。
3. v3.15 新增了 `ChatPipeline` 失败判定；订单号消息在房卡分支前遇到校验、限流或 Pipeline 异常时会直接 `continue`，因此可能不再发送原来的 A 卡片。
4. v3.15 的 `chat.html` 安全改动只允许 HTTPS，合法 `weixin://dl/business/?t=...` 网页链接也被拦截；该问题单独修复，但不能改变 A 卡片样式。

## 二、修复边界

### 1. 微信客服订单号必须固定走 A

订单号匹配后：

- 使用 `sendKfMiniprogramMessage()`；
- `appid` 使用宿家 `share_bundle.miniapps[0].appid`；
- `pagepath` 原样使用宿家 `share_bundle.miniapps[0].path`；
- `title`、`thumb_media_id` 保持现有规则；
- 不调用 `sendKfLinkMessage()` 作为样式替代；
- A 卡片发送失败时只发文字提示，不发送 B 卡片冒充成功。

### 2. 房卡分支独立于 AI Pipeline 成功与否

订单号的核心动作是查询并发送宿家房卡，不应因为 AI 回复生成失败而跳过。保留 Pipeline 用于普通文本和日志，但订单号即使 Pipeline 返回失败，也继续进入 A 房卡发送流程。

### 3. 网页协议白名单

图片仍只允许 HTTPS；网页卡片点击链接允许 HTTPS 或严格匹配 `weixin://dl/business/?t=[A-Za-z0-9_-]+`。这只修复链接点击，不改变微信客服 A 卡片。
