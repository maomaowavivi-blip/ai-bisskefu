## 一、事故回顾

8/25 客户查询订单 123456789,两张云房卡全部 `errcode=40007`(thumb_media_id 无效)。

根因(v3.15.5 设计缺陷):`buildRoomCardDeliveries()` 先读 DB 的
`ai.roomcard.thumb_media_id`,非空即短路;而 60h 过期检查+自动重传写在
`getThumbMediaIdCached()` 里 → 永远执行不到。8/18 上传的 thumb 在 8/21
超过企微 72h 有效期后,系统持续使用死 thumb。

## 二、修复设计(方案 C:A + 发送失败自愈)

### 2.1 A 部分:修读取顺序

`buildRoomCardDeliveries()`(wecom_kf_roomcard_v37.php:291-297)
及同文件其他两处相同模式(325/351 行附近):

```php
// 旧(错): DB 非空短路,绕过过期检查
$thumb = trim((string)pcGet($db, 'ai.roomcard.thumb_media_id', ''));
if ($thumb === '') { $thumb = getThumbMediaIdCached() ?? ''; }

// 新(对): 一律经过 getThumbMediaIdCached() 的 60h 检查+自动重传
$thumb = getThumbMediaIdCached() ?? '';
```

DB(pcSet)保留为同步副本,仅作运维排查用途,不再作为读取源。

### 2.2 C 部分:发送失败自愈(wecom_kf.php 发卡处)

现状:`sendKfMiniprogramMessage()` 返回 errcode,40007 时直接放弃该卡。

新增流程(buildRoomCardDeliveries 调用方循环内):

```
对每张 delivery:
  resp = sendKfMiniprogramMessage(...thumb...)
  若 errcode == 40007:
    forceRefreshThumbCache()          // 删缓存文件 → 重传 → 写缓存+DB
    newThumb = getThumbMediaIdCached()
    若 newThumb 非空且 != 旧 thumb:
      delivery['thumb_media_id'] = newThumb
      resp = sendKfMiniprogramMessage(...重发这一张...)
  记录最终结果,继续下一张卡
```

要点:
- 只针对 40007 触发自愈(其他错误码不重试,避免重复发卡骚扰客户)
- 自愈只重发**当前这张**卡,N 张卡共用新 thumb,后续卡直接用新值
- `forceRefreshThumbCache()` 新函数:unlink 缓存文件后调 getThumbMediaIdCached()
- 幂等安全:40007 表示消息未发出,重发不会造成客户收到两张卡

### 2.3 辅助清理

上线时清一次 DB 死 thumb(pcSet 置空),让首次请求就走重传路径,
不等下一次自然过期。

## 四、失败模式分析

| 场景 | 行为 |
|---|---|
| 缓存有效 | 直接发,零额外开销 |
| 缓存超 60h | 取 thumb 时自动重传(1s),客户无感 |
| thumb 提前被企微作废 | 发送得 40007 → 自愈重传+重发,客户多等 ~1s |
| 连续两次上传失败(企微故障) | 该单走兜底文案;下一个客户到来时再次尝试自愈 |
| 宿家接口失败 | 与本次无关,维持现有兜底 |
