## 一、需求与结论

**需求**：把「转人工 400 电话兜底」的**完整回复文案**从代码硬编码改为**管理后台可编辑**，苏鸣以后自己点保存即可改，不再走开发 + 部署。

**结论：做，但只做「一个配置键 + 一个后台输入框」，不做完整配置中心。**

理由（成本收益）：
- 后台「AI 行为规则」页当前是**纯只读**（`agentField()` 渲染成 `<div>`），且全站没有任何页面调用 `api/agent.php?action=save_config`（只有 `get_config`）→ 「后台功能」不是开个开关，是要从零建输入框 + 保存按钮
- 但 `api/agent.php:65-96` 的 `save_config` 接口**已存在**且只校验 `agent.` / `plugin.` 前缀（`:80-82`），新键**不用改白名单** → 增量成本只有「前端一个输入框 + 后端 2 行读取」
- 400 号码 + 兜底话术是**低频值**（一年 0~1 次），为它建完整配置中心收益低于成本；一次投入换永久免部署，划算

## 三、审计发现的 3 个既有不一致（本次一并修，否则「改配置」会自相矛盾）

### 3.1 缺陷①：prompt 里注入的是 v3.7 旧话术，v3.11 的修正被 DB 值覆盖

- `api/PromptEngine.php:82-88`：`handoff_system_hint` **DB 有值** → 走 if 分支；`:91` 的 else 分支（v3.11 改过的 400 文案）**永远走不到**
- DB 值仍是 `正在为您转接人工客服，请稍候。` → LLM 分支被指示说「正在转接人工」，而真实兜底是 400 电话
- 根因：`templates/homestay/agent_defaults.json` 与 `scripts/migrate_agent_config.php:32` 里还是 v3.7 文本，v3.11 只改了代码没改数据

### 3.2 缺陷②：LLM 分支说 400 话术会被终检替换成拒答句

`api/PromptEngine.php:198-216` `finalizeReply`：无 KB 命中时，回复不含 preserved marker → **一律替换成 `agent.fallback.reply`（拒答句）**
`api/PromptEngine.php:219-230` `isPreservedReplyWithoutKb` 的 marker 来自 DB，DB 值**不含 `400-155-9959`**
（代码里的 fallback 默认 `['400-155-9959', …]` 被 DB 覆盖）

→ 一旦把 prompt 改成让模型说 400 话术，**LLM 分支会把它吃掉换成拒答句**。只做配置化不做这步 = 功能是坏的。

### 3.3 缺陷③：C1 与 C2 差一个全角波浪号 `～`

主链路带 `～`，openapi 不带 → 同一句话两个渠道两种输出。

## 四、方案设计

### 4.1 配置键

| 项 | 值 |
|---|---|
| 键名 | `agent.handoff.reply` |
| 存哪 | `platform_config`（`api/agent.php?action=save_config` 已支持任意 `agent.*` 键，无需改白名单） |
| 默认值 | `请拨打 400-155-9959 联系管家～`（PHP 常量，**不入模板**） |
| 生效范围 | H5 / 微信客服 / 企微 / openapi 全部渠道 |

**为什么不写进 `templates/*/agent_defaults.json`**：
`api/IndustryTemplate.php:34-66` `importAgentDefaults()` 会把模板里的键 **upsert 覆盖** DB 值。
若把默认文案放进模板，苏鸣在后台改好的话术会被「应用行业模板」一键冲回默认。
→ 默认值只放 PHP 常量；`apply_industry_template` 不含该键 → 不会覆盖后台值。

### 4.2 取值优先级与「立即生效」

```
platform_config.agent.handoff.reply（pcGet 直查 DB）
    ↓ 为空
PHP 常量 PromptEngine::HANDOFF_REPLY_DEFAULT
```

**必须用 `pcGet()`（`api/config.php:176`，每次直查 DB），不能用 `AgentConfig::get()`**：
`AgentConfig::$cache`（`api/AgentConfig.php:46-60`）是**进程级静态、无 TTL、无跨进程失效**，
`clearCache()`（`:93-95`）只清当前进程。php-fpm 多 worker 下，后台保存后其它 worker 仍读旧值 → 「保存了没生效」。
用 `pcGet` 天然绕开该问题。

### 4.3 代码改动清单（6 处 + 1 个新方法）

| 文件 | 改动 |
|---|---|
| `api/AgentConfig.php` | 新增 `getFresh($key, $default)`：直查 DB，绕过静态缓存（5 行） |
| `api/PromptEngine.php` | 新增常量 `HANDOFF_REPLY_DEFAULT` + 静态方法 `handoffReply(?AgentConfig, ?PDO)`（唯一取值入口） |

| `api/PromptEngine.php:113` | 服务边界改用 `handoffReply($config)` |

| `api/PromptEngine.php:82-88` | `handoffHint` 增加 `{reply}` 占位符替换 |
| `api/PromptEngine.php:219-230` | `isPreservedReplyWithoutKb` 增加「含当前兜底话术整句 → 保留」，不再依赖 markers 里写死号码 |

### 4.4 生产数据变更（SQL，随部署执行）

```sql
-- ① 建配置键（默认值与现网行为一致，插入后无行为变化）
INSERT INTO platform_config (`key`, `value`, `remark`)
VALUES ('agent.handoff.reply', '请拨打 400-155-9959 联系管家～', 'v3.24:转人工兜底话术')
ON DUPLICATE KEY UPDATE `remark` = VALUES(`remark`);

-- ② 修 prompt 注入的旧话术：{reply} 占位 → 由代码替换为当前生效话术
UPDATE platform_config
SET `value` = '【必须直接转人工】以下问题只回复"{reply}"，不再转接人工，不做其他回答\n涉及：发票、续住、换房、退款、投诉、赔偿、押金纠纷等；具体以系统「转人工规则」词库为准'
WHERE `key` = 'agent.rules.handoff_system_hint';
```

- ① 的 `ON DUPLICATE KEY UPDATE remark`：**不覆盖已有 value**（若苏鸣已先改过话术，保留他的值）
- ② 只改 `handoff_system_hint` 一条，不动 `preserved_markers`（缺陷②由代码层解决，不依赖 DB markers）
