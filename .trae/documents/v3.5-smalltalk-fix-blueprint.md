# 修改蓝图:SmallTalk 闲聊被"无 KB 锁 fallback"问题修复

**日期**:2026-08-13
**作者**:波尼(执行),苏鸣(审核)
**状态**:待审计

---

## 一、问题

**现象**:用户发"晚上好/你好/谢谢"等闲聊,AI 回复固定 fallback"这边暂时没有查到准确信息,建议您联系前台确认。"而不是自然闲聊。

**根因**(有代码证据):
- `SmallTalkWorkflow::handle()` 调用 `PromptEngine::buildMessages($persona, $history, $message, [], ...)` 传 **kbItems=[]**
- `buildMessages` → `buildUserTurn($message, [], $config)` 第 240-242 行:
  ```php
  if (empty($validKb)) {
      $lines[] = '【本轮约束】当前无【参考资料】。';
      $lines[] = '不得输出任何具体业务事实，只回复：' . $fallback;
  }
  ```
- LLM 收到"只回复 fallback"指令 → 闲聊也被强制回 fallback

**验证**:生产 curl "晚上好" → `intent=SMALL_TALK, workflow=SmallTalkWorkflow, reply="晚上好，这边暂时没有查到准确信息…"`(已实测)

---

## 二、方案对比

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. SmallTalkWorkflow 不调 buildMessages,用轻量闲聊 prompt** | 单独构造 `[system, user]` 数组,不含"无资料回 fallback"约束 | 根治;闲聊自由 | 与 buildMessages 风格不一致 |
| **B. buildMessages 加 $allowNoKbChat 参数** | 传 true 时 buildUserTurn 不追加"只回复 fallback" | 复用现有管道;改动小 | 需动 buildMessages 签名,影响所有调用方 |
| **C. buildUserTurn 检测到 SMALL_TALK 意图时跳过约束** | 需传 intent 上下文 | 语义清晰 | 侵入式,耦合 Intent |

**推荐 A**:SmallTalkWorkflow 本来就该独立构造 prompt(闲聊不需要 KB 检索、不需要事实约束),改动局部、风险最低、不污染通用管道。

## 三、方案 A 详细设计

### 修改文件:api/Workflow/SmallTalkWorkflow.php

**位置**:`handle()` 方法,第 28-52 行(LLM 生成部分)

**改前**:
```php
// 其他闲聊(天气、问候等)→ 走 LLM
$stmt = $this->db->query('SELECT * FROM persona_config ORDER BY id DESC LIMIT 1');
$persona = $stmt->fetch() ?: [];
$messages = PromptEngine::buildMessages(
    $persona,
    $this->intentCtx->sessionState['history'] ?? [],
    $message,
    [],
    $this->sessionId,
    $message,
    $this->config
);
$result = callAI($messages, [...]);
```

**改后**:
```php
// 其他闲聊(天气、问候等)→ 走 LLM
// v3.5 修复：不再用 buildMessages(它带"无资料只回 fallback"约束,会锁死闲聊)
// 改用轻量闲聊 prompt,让 LLM 自然回应
$stmt = $this->db->query('SELECT * FROM persona_config ORDER BY id DESC LIMIT 1');
$persona = $stmt->fetch() ?: [];
$name = trim($persona['name'] ?? '客服');
$personality = trim($persona['personality'] ?? '友好、亲切');
$speakStyle = trim($persona['speak_style'] ?? '');

$system = "你是{$name},柚光民宿的 AI 客服。客人正在和你闲聊(打招呼/寒暄/表达情绪),请用自然、简短、友好的中文回应。
性格：{$personality}
说话风格：{$speakStyle}
规则：
1. 只回应闲聊内容,不要编造任何民宿业务事实(入住时间、房价、设施等一律不谈,除非客人明确问)
2. 回复 20-60 字,一句话即可
3. 可以自然引导:如果客人有具体问题,可以提示"有什么入住或订单问题都可以问我~"
4. 不要使用"这边暂时没有查到准确信息"等客服兜底话术";

$messages = [
    ['role' => 'system', 'content' => $system],
    ['role' => 'user', 'content' => $message],
];

$result = callAI($messages, [
    'max_tokens' => 80,
    'temperature' => 0.7,
    'thinking' => ['type' => 'disabled'],
]);
```

### 不修改的文件
- `api/PromptEngine.php` — 通用管道不动,避免回归
- `api/ChatPipeline.php` — 不动
- 其他 Workflow — 不动

## 四、影响面

| 文件 | 改动 | 风险 |
|---|---|---|
| `api/Workflow/SmallTalkWorkflow.php` | 替换 LLM 消息构造(约 20 行) | 低:仅影响闲聊分支 |

**回归风险**:
- 只影响 SMALL_TALK 意图的回复内容
- 知识问答/订单/房间等其余意图完全不受影响
- `isFlowExitMessage`(谢谢/再见等固定话术)分支保留不动
