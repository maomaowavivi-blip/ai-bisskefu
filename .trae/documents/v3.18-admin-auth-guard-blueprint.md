# v3.18 Admin 后台统一登录守卫(auth-guard)蓝图

> 日期: 2026-08-24
> 提出人: 苏鸣("b"方案拍板)
> 执行人: 波尼

## 一、问题(根因)

后台 `chat-logs.html` 打开显示"暂无对话记录",实为 **token 过期后 401 错误被前端静默吞掉**,误显示为空状态。

证据链:
- 服务端实测 `/api/chat.php?action=logs` 有效 token 返回 `code:0` + 463 会话(HTTP 200)
- 前端 `loadList()` 只判 `res.code === 0`,非 0 一律走 else 显示"暂无对话记录"
- 页面头部仅检查 localStorage 是否存在 token,**不校验有效性**
- JWT 过期后页面照样打开,请求全部 401

## 二、历史遗留

`admin/auth-guard.js`(完整实现:查 token → `auth.php?action=me` 校验 → 失效清除并跳 login)**早已写好,但 0 个页面引用**。各页面均为 inline 简化版检查。

## 三、改动范围

### 3.1 加 `<script src="auth-guard.js"></script>` 到 `<head>`(7 个页面)

| 页面 | 备注 |
|---|---|
| admin/chat-logs.html | 主诉求页 |
| admin/dashboard.html | |
| admin/handoff.html | ⚠️ AGENTS.md 第4节:线上在用,不可删除,本改动只是加一行 script,安全 |
| admin/knowledge.html | |
| admin/persona.html | 此前连 `if(!token)` 都没有,守卫补齐 |
| admin/settings.html | |
| admin/users.html | |

**不加**: admin/login.html(已有"已登录跳 dashboard"逻辑,加守卫有循环跳转风险)

### 3.2 chat-logs.html 错误显示增强

`loadList()` / `loadStats()` / `viewDetail()` 增加:
- `res.code === 401`: 提示"登录已过期,正在跳转登录页..."并跳 login
- 其他非 0 code: 表格区显示具体错误 msg(不再假装"暂无对话记录")
- 真空数据才显示原"暂无对话记录"

## 四、不改的东西

- 不改任何 PHP(API 行为不变)
- 不删各页面现有 `var token = ...` 与 `getHeaders()`(守卫先于页面脚本执行跳转,二者共存无冲突)
- 不动 handoff 三件套的删除/重构(AGENTS.md 禁区)

## 五、时序说明(已知可接受的瑕疵)

守卫校验是异步的,页面脚本可能先用旧 token 发出请求(401),随后守卫完成校验跳登录。
chat-logs 的错误增强会让这瞬间显示"登录已过期"提示而非空白,体验可接受。

## 六、验证方案

1. 本地 grep 确认 7 页均有 `<script src="auth-guard.js">`
2. 上 VPS 后浏览器实测两场景:
   - token 有效: chat-logs 正常显示 463 会话列表
   - localStorage 清空/篡改 token: 自动跳 login.html
3. md5 校验本地 == VPS

## 七、回滚

纯静态 HTML/JS 改动,git revert + scp 覆盖即回滚,无需 reload php-fpm。
