# v3.14 云房卡切换 A 样式原生小程序卡片蓝图

## 1. 决策

按用户明确要求，将订单号自动回复从 B 样式 `link` 卡片切换为 A 样式微信客服原生 `miniprogram` 卡片。

本次只改变发送消息类型，不改变宿家接口、订单查询、房间号标题提取和固定封面逻辑。

## 2. 数据来源

客户发送渠道订单号后：

1. 调用宿家 `byChannelOrder` 查询云房卡。
2. 查询不到时才调用 `generateByChannelOrder`。
3. 从 `share_bundle.miniapps[0]` 读取：
   - `appid`
   - `path`，映射到企微发送字段 `pagepath`
4. 从宿家 `shareText` 提取面向客户展示的房间号。
5. 使用现有 `thumb_media_id` 作为固定封面。

## 3. 发送

调用企业微信客服 `kf/send_msg`：

- `msgtype`: `miniprogram`
- `miniprogram.appid`: 宿家返回的 `appid`
- `miniprogram.pagepath`: 宿家返回的 `path`
- `miniprogram.title`: “您的房间为 房间号”
- `miniprogram.thumb_media_id`: 当前固定封面素材

发送接口明确失败时返回文字提示。本版本不再自动发送 B 样式链接卡片。

## 4. 已完成审计

测试订单只读查询已确认：

- `appid` 非空。
- `path` 指向 `pages/index/index`。
- `path` 包含 `qrCodeId`。
- `qrCodeId` 与宿家返回的 `encryptedId` 一致。
- 房间号标题能够从 `shareText` 正确提取。

宿家程序员已反馈小程序入口处理完成。本次验收必须通过客户从微信正常输入订单号触发，不能只以服务器手工调用返回 `errcode=0` 作为成功标准。

## 5. 修改文件

- `api/wecom_kf.php`
- `.trae/documents/v3.14-roomcard-native-miniprogram-blueprint.md`

## 6. 验收标准

1. PHP 语法检查通过。
2. 构建结果包含真实房间号标题、宿家 appid、宿家原始 path 和封面素材。
3. 从微信客户端正常发送测试订单号。
4. 生产回调日志显示 `Sent roomcard miniprogram message`。
5. 微信客户端实际收到 A 样式卡片。
6. 点击后一步进入对应云房卡，不出现空白页。
7. 本地与 VPS md5 一致，PHP-FPM reload 正常。

## 7. 安全与回滚

- 不改数据库，不记录订单号、房间号、客户 ID 或跳转令牌。
- 如正常链路仍无法送达或打开，恢复 v3.13 的 B 样式发送代码。

## 8. 蓝图审计结论

审计通过，可以进入代码修改和正常微信回调实测。
