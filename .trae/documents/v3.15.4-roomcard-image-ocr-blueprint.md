## 一、根因

v3.15.3 修复了"纯中文带订单号"文本消息被识别成 SMALL_TALK 的问题。但还有两类消息**根本进不到闸门逻辑**:

1. **图片消息**: `api/wecom_kf.php:273` 的 `if ($msgType !== 'text') continue;` — 直接 skip
2. **未来扩展的语音/文件**:同上 skip

客户实际场景:截了订单详情图、拍了小票、发了平台订单截图 — 这些图里通常有订单号,但被机器人装死。

**根因**:闸门逻辑只覆盖 text 消息体,OCR/ASR 链路完全缺失。

## 二、方案

### 2.1 接住图片(范围 A)

**文件**:`api/wecom_kf.php`

**改动1**:第 268-276 行的 msgtype 过滤
```php
// 旧:
if ($msgType !== 'text' || empty($from) || empty($content)) {
    wecom_kf_log('Skip unsupported message type=' . $msgType);
    continue;
}

// 新:
if ($msgType === 'event' || empty($from)) {
    wecom_kf_log('Skip unsupported message type=' . $msgType);
    continue;
}
// 放过 text / image / voice / file
```

**改动 2**:新增 msgtype 分支处理
```php
// 在 $trimmedMsg 赋值前:
$extractedText = ''; // OCR/原文统一进这里
if ($msgType === 'text') {
    $extractedText = $msg['text']['content'] ?? '';
} elseif ($msgType === 'image') {
    $picUrl = $msg['image']['pic_url'] ?? '';
    if ($picUrl !== '') {
        $extractedText = ocrImageFromUrl($db, $picUrl, $from); // 新增函数
        wecom_kf_log('image OCR from=' . substr(sha1($from), 0, 10)
            . ' text_len=' . strlen($extractedText));
    }
}
// voice/file:留待后续,本版本不接
```

**新增函数**:`ocrImageFromUrl(\PDO $db, string $picUrl, string $from): string`
- 用企微 access_token(已有)+ `media/get` 接口下载图片 → 临时文件
- POST 到 `http://127.0.0.1:9003/ocr`(RapidOCR 服务)
- 返回识别出的纯文本
- 失败/超时(> 10s)→ 返回空字符串 + 错误日志,不影响后续 LLM 路径

**关键:文本 vs 图片统一进 `$extractedText`**,后续闸门只看这个变量。

### 2.2 闸门统一入口(范围 B)

**新增文件**:`api/helpers/order_candidate.php`

```php
<?php
declare(strict_types=1);

/**
 * v3.15.4:统一订单号提取入口
 * 输入:任意文本(text 原文 / OCR 识别文本 / 后续 ASR 文本)
 * 输出:首个 8-30 位连续数字串;无则空字符串
 *
 * 失败场景:客户发"你好" / "几点入住" / "手机 13800138000" → 命中但 API 兜底
 * 真人发"我的订单号是5035035963841932965" → 命中 → 查订单 / 发云房卡
 */
function extractOrderCandidate(string $text): string
{
    if ($text === '') return '';
    // 8-30 位连续数字串。允许中文/英文/标点包围(用 \b 边界)
    if (preg_match('/\b(\d{8,30})\b/', $text, $m) === 1) {
        return $m[1];
    }
    return '';
}
```

**`wecom_kf.php` 改造点**:第 286-296 行的闸门逻辑简化为调用此函数
```php
$trimmedMsg = trim($extractedText);
$orderCandidate = extractOrderCandidate($trimmedMsg);
$isOrderMessage = ($orderCandidate !== '');
```

### 2.4 OCR 服务部署(VPS 端,独立子任务)

**VPS 环境**:
- 43.138.217.6 (root,生产路径 /www/wwwroot/aibisskefu)
- Python 3.11.6 ✅ / pip 未装
- 3.6G 内存 / 62G 磁盘 / 2 核 CPU
- **无 docker**(轻量云不带)

**部署路径**:**不用 docker**,用 Python venv + systemd 守护 `rapidocr_web`(官方提供的 Flask HTTP 服务)。

**部署步骤草案**(实施前会单独走"生产部署子蓝图"):
1. `apt install -y python3-pip python3-venv`
2. `python3 -m venv /opt/rapidocr-venv`
3. `/opt/rapidocr-venv/bin/pip install rapidocr_web`
4. 写 systemd unit `/etc/systemd/system/rapidocr.service`(监听 127.0.0.1:9003,只对 localhost 开放)
5. `systemctl enable --now rapidocr`
6. `curl http://127.0.0.1:9003/` 验证健康

**性能预期**(3.6G 内存,CPU):
- 中文单图识别 1-3 秒(图片 < 2MB)
- 模型 ~50MB,常驻内存 ~200MB
- 并发:rapidocr_web 默认单线程,串行处理。客户并发低,够用

**PII 安全**:RapidOCR 跑在 localhost,不联网。订单截图绝不会出 VPS — 符合苏鸣隐私红线。

## 三、风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| OCR 服务挂了 → 客户图片被丢 | 中 | ocrImageFromUrl 失败返空字符串,图片消息退化为走 LLM(KB 答"请发订单号") |
| OCR 误识别手机号/身份证为订单号 | 低 | 失败路径 → buildRoomCardDelivery → 兜底文案(你 8/18 已授权接受)|
| 图片消息没塞 pic_url 字段 | 低 | 走 LLM,不报错 |
| 企微临时素材 3 天过期 | 无影响 | 客户发图时是"事件当下",实时下载 |
| PHP 调用 OCR 超时(> 10s) | 低 | curl timeout=10s + try/catch + 失败不影响后续流程 |
| RapidOCR 服务被外部访问 | 中 | systemd unit 绑定 127.0.0.1,非 localhost 拒绝 |
| OCR 文本很长(>600 字) | 极低 | mb_substr 截断,与文本消息保持一致 |
| 内存溢出 | 极低 | 限制图片大小(企微客服图片 < 10MB),CURLOPT_MAXFILESIZE=10MB |
