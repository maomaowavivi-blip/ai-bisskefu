# v3.16 修改蓝图:云房卡一单多房 - N 张卡发 N 张

**日期**:2026-08-20
**作者**:波尼(执行),苏鸣(审核)
**状态**:待审计

---

## 一、需求

宿家 `generateByChannelOrder` 已支持"一单多房",返回 `cards` 数组(每张含独立 `qrCodeId`、`share_bundle`、`urlLink`)。

**现状**:AI 客服(`wecom_kf_roomcard_v37.php`)调用时**只取 `cards[0]`**,只发一张云房卡。即使是双床房 / 多人入住,客户也只看到一张卡。

**目标**:宿家返回 N 张 → AI 客服**发 N 张独立的云房卡卡片**(顺序一致),中间可加一句文字引导。

---

## 二、根因(8/20 实测确认)

`api/wecom_kf_roomcard_v37.php` 当前逻辑:
- 第 28 行 `getRoomCard`:返 `$data['data']['list'][0]` ← 只拿一张
- 第 62 行 `generateRoomCard`:返 `$data['data']['cards'][0]` ← 只拿一张
- 第 274 行 `buildRoomCardDelivery`:输入是**单卡**,输出是**单 delivery**
- `api/wecom_kf.php` 调发卡逻辑只发一次 `sendKfMiniprogramMessage`

8/20 苏鸣贴的宿家原始返回里 `data.cards` 有 2 条(107/108,房间 1002/1001),我们只发了 1002。

---

## 三、方案

### 3.1 新增 `buildRoomCardDeliveries`(批量子集)

新增函数,**不改 `parseRoomCardDelivery`**(单卡解析逻辑不变,沿用现有可靠性):

```php
/**
 * v3.16:一次返回当前订单的全部房卡 delivery 数组。
 * 宿家可能返回 1~N 张,每张都是独立的云房卡。
 * @return array[] 每个元素是 parseRoomCardDelivery + thumb_media_id 的结果
 */
function buildRoomCardDeliveries(PDO $db, string $channelOrderId): array {
    $cards = generateAllRoomCards($db, $channelOrderId);
    if (!$cards || !is_array($cards)) return [];

    // thumb 一次性取好(避免重复上传/DB 查询)
    $thumb = trim((string)pcGet($db, 'ai.roomcard.thumb_media_id', ''));
    if ($thumb === '') {
        $thumb = getThumbMediaIdCached() ?? '';
    }
    if ($thumb === '') return [];
    @pcSet($db, 'ai.roomcard.thumb_media_id', $thumb);

    $deliveries = [];
    foreach ($cards as $card) {
        if (!is_array($card)) continue;
        $parsed = parseRoomCardDelivery($card);
        if (!$parsed) continue;
        $parsed['thumb_media_id'] = $thumb;
        $deliveries[] = $parsed;
    }
    return $deliveries;
}

/**
 * v3.16:调 generateByChannelOrder 拿所有 cards。
 * 与 generateRoomCard 区别:返 cards 数组本身而非 [0]。
 */
function generateAllRoomCards(PDO $db, string $channelOrderId): ?array {
    $user = trim(pcGet($db, 'roomcard.username', ''));
    $pwd  = trim(pcGet($db, 'roomcard.password', ''));
    if ($user === '' || $pwd === '') return null;

    $url = "https://apicenter.sujia365.com/index.php/openapi/room_card/generateByChannelOrder"
        . "?username=" . urlencode($user)
        . "&pwd=" . $pwd
        . "&channel_order_id=" . urlencode($channelOrderId);

    $ch = curl_init($url);
    curl_setopt_array($ch, [
        CURLOPT_POST => true,
        CURLOPT_POSTFIELDS => [],
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_TIMEOUT => 15,
    ]);
    $resp = curl_exec($ch);
    $httpCode = curl_getinfo($ch, CURLINFO_HTTP_CODE);
    curl_close($ch);

    if ($httpCode !== 200 || !$resp) {
        error_log('[roomcard] generateAll HTTP fail: ' . $httpCode);
        return null;
    }
    $data = json_decode($resp, true);
    if (!isset($data['code']) || intval($data['code']) !== 1) return null;
    if (empty($data['data']['cards']) || !is_array($data['data']['cards'])) return null;
    return $data['data']['cards'];
}
```

### 3.2 改 `api/wecom_kf.php` 调用方

原代码(单张发卡,大致):
```php
$delivery = buildRoomCardDelivery($db, $candidate);
if ($delivery) {
    sendKfMiniprogramMessage($externalUserId, $delivery);
}
```

新代码(批量发卡):
```php
$deliveries = buildRoomCardDeliveries($db, $candidate);
$cardCount = count($deliveries);

// 2 张及以上:加文字引导
if ($cardCount >= 2) {
    sendKfTextMessage($externalUserId, sprintf(
        '您一共订了 %d 间房,以下是各房间的云房卡～', $cardCount
    ));
}

foreach ($deliveries as $delivery) {
    sendKfMiniprogramMessage($externalUserId, $delivery);
}

if ($cardCount === 0) {
    // 兜底文案(与 v3.15.5 时代一致)
    sendKfTextMessage($externalUserId, '暂时未能打开您的云房卡,请稍后重试或联系前台。');
}
```

**注意**:`sendKfTextMessage` 用法得对齐 wecom_kf.php 现有的文本消息发送函数(查一下名字)。

### 3.3 `parseRoomCardDelivery` **不动**

它能正确解析单卡,扩到多卡只需循环调用,业务逻辑零变更。

### 3.4 不动的地方

- `parseRoomCardDelivery` / `parseRoomCardForLink`
- `getRoomCard`(保留旧函数,未来可能仍有调用)
- ChatPipeline / IntentRouter / OrderQueryWorkflow / RoomQueryFlow
- `buildRoomCardDelivery`(保留旧函数,但 wecom_kf.php 改调新函数)

## 四、改动前后对比

| 场景 | 旧 | 新 |
|---|---|---|
| 单房订单 | 发 1 张云房卡 ✅ | 发 1 张云房卡 ✅ |
| 双房订单 | 发 1 张云房卡(只发了 1002,客户没拿到 1001)| 发 1 句文字引导 + 2 张云房卡(1002、1001)✅ |
| 三房订单 | 发 1 张云房卡 ❌ | 发 1 句文字引导 + 3 张云房卡 ✅ |
| 宿家返 0 张 | 走兜底文案 | 走兜底文案 |
| `parseRoomCardDelivery` 失败某张卡 | N/A | `continue` 跳过,其他卡正常发 |

## 五、风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 企微拒收连续多条消息 | 极低 | 客服消息无数量限制,业内订机票/订酒店普遍连发 |
| 房卡数过多(>5)| 低 | `if ($cardCount > 5) array_slice($deliveries, 0, 5)` + 提示"剩余房间请联系前台"|
| thumb 频繁调用 pcSet | 极低 | 一次循环只 set 一次(已经优化)|
| 兜底文案重复(发完卡又发兜底) | 中 | 用 `else if` 或计数器确保只走一个分支 |
| `parseRoomCardDelivery` 失败导致 0 张 | 低 | 显式 `error_log` + 继续走兜底文案 |
| `getRoomCard` 旧函数残留 | 极低 | 不删,只留作后备(未来若发现 generate 失败回退) |
