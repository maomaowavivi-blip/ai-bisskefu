# v3.32 房卡生成限制：非入住日不自动生成房卡 — 蓝图

> 2026-11-20 起草。状态：待实现（口径已由苏鸣拍板）。

## 1. 需求（苏鸣 2026-11-20）

客户输入订单号时，若订单**不是今日入住**，不自动生成云房卡，回复告知。
例：3 号下单、6 号入住 7 号离店，4 号输入订单号 → 不生成房卡；6 号（入住当天）输入 → 正常生成。

### 已拍板口径（苏鸣 2026-11-20 问卷）

| # | 口径 | 决定 |
|---|---|---|
| 1 | 回复形态 | **保持两条**：先订单信息，再提示 |
| 2 | 已离店场景 | 回复"订单有效期已过"语义（= 中台原文"该订单已过期，无法生成房卡"） |
| 3 | 话术来源 | **透传中台原文，只把「！！！」改成「。」** |

## 2. 实测事实（关键：这个规则中台早已实现）

中台房卡接口 `room_card/byOrder` 对不同状态的返回（生产实测）：

| 订单状态 | 中台返回 |
|---|---|
| 今日入住 | `code=1` + `data.cards[]`（正常发卡） |
| **未到入住日** | `code=0, msg="入住当天才能自助生成云房卡哦，请当天再来生成入住云房卡！！！"` |
| 已过离店日 | `code=0, msg="该订单已过期，无法生成房卡"` |

**中台规则与话术与需求完全一致**。问题在我们这层：

### 问题 1：中台原因被丢弃

`api/wecom_kf_roomcard_v37.php` `buildRoomCardDeliveries()` 把 `$err` 只写 error_log，
对外统一回「暂时没有查找到您的云房卡，请稍后重试或联系管家。」
→ 客户以为是系统坏了或订单不存在，反复问。

### 问题 2：中文被按字节截断

`fetchCenterRoomCards()` 的 `substr((string)$data['msg'], 0, 60)` —— `substr` 按**字节**，
中文 3 字节/字，60 字节只够 20 字 → 日志里变成"…请当天再来"，完整话术被砍掉。

### 问题 3（本次新发现，影响形态）：非入住日时客户收不到订单信息

`api/wecom_kf.php:443-455`：

```php
$roomCardSent = $sentCount > 0;
if (!$roomCardSent) {
    $roomCardSent = sendKfMessage($from, '暂时没有查找到您的云房卡…', $useOpenKfId);
}
...
if ($roomCardSent) { markMsgProcessed($msgId); continue; }   // ← 跳过 $replyText
$sent = sendKfMessage($from, $replyText, $useOpenKfId);      // ← 订单信息在这行
```

`$roomCardSent` 被赋成"兜底文案是否发送成功"，于是房卡发不出时 `continue`，
**订单信息 `$replyText` 永远发不出去**。现状 = 客户只收到一句"暂时没有查找到"。

## 3. 方案

### 3.1 `api/wecom_kf_roomcard_v37.php`

- `fetchCenterRoomCards(PDO $db, string $channelOrderId, ?string &$err = null, ?string &$bizMsg = null): array`
  - 新增 `$bizMsg` 出参：中台的**原始业务消息**（`$data['msg']`，未加工）
  - `substr(...,0,60)` → `mb_substr(...,0,60,'UTF-8')`（修中文截断）
- `buildRoomCardDeliveries(PDO $db, string $channelOrderId, ?string &$err = null, ?string &$bizMsg = null): array`
  - 透传 `$err` / `$bizMsg`（当前内部吞掉了）
- 新增 `centerRoomCardReply(?string $bizMsg): string`
  - 有 bizMsg → 清洗后返回：`rtrim` + 把结尾连续「！」替换成一个「。」+ 补句号（无标点时）
  - 无 bizMsg → 返回空串（调用方回落到原兜底文案）

### 3.2 `api/wecom_kf.php`（房卡发送段）

```
$cardErr = null; $cardBizMsg = null;
$deliveries = buildRoomCardDeliveries($db, $orderCandidate, $cardErr, $cardBizMsg);
...
if (!$roomCardSent) {                      // 房卡没发出去
    $tip = centerRoomCardReply($cardBizMsg);
    if ($tip === '') $tip = '暂时没有查找到您的云房卡，请稍后重试或联系管家。';
    // 口径1：两条 —— 先订单信息，再原因提示
    if (trim($replyText) !== '') sendKfMessage($from, $replyText, $useOpenKfId);
    $roomCardSent = sendKfMessage($from, $tip, $useOpenKfId);
}
```

- 房卡**发得出去**时的行为**完全不变**（仍只发房卡，不发订单信息）
- 房卡发不出 → 现在发两条：① 订单信息（`$replyText`）② 原因提示（中台原文清洗）
- `$roomCardSent` 语义回归"本次已回复"，`continue` 不再吃掉订单信息
- 中台不可用（HTTP 失败/超时）→ 无 bizMsg → 回落到原兜底文案

### 3.3 不动的地方

- `api/Workflow/OrderQueryWorkflow.php` 的回复内容与结构不动（口径1 = 保持两条，第一条沿用现有订单信息）
- 入住日当天发卡成功路径不动
- H5 / 小程序 / openapi 渠道不动（只有微信客服会自动发房卡）

## 4. 影响面与回滚

| 项 | 影响 |
|---|---|
| 微信客服订单号消息 | 非入住日/已过期：从"1 条兜底文案"变为"2 条（订单信息 + 原因提示）"；入住日：不变 |
| 中台调用次数 | **不变**（仍只调 1 次房卡接口）——不额外查订单，省一次中台调用 |
| 其它渠道 | 无影响 |
| 回滚 | `git revert` + scp 覆盖 2 个文件 + php-fpm reload |

## 5. 验收标准

1. **未到入住日**（生产真实订单 `5044043382465945633`，入住 2027-02-10）：
   - 中台 bizMsg 透传后 = 「入住当天才能自助生成云房卡哦，请当天再来生成入住云房卡。」（结尾是句号，非「！！！」）
2. **已过期**（生产真实订单 `1128148162721995`，入住 2026-05-26）：
   - 提示 = 「该订单已过期，无法生成房卡」
3. **中台不可用**（url 配错模拟）→ 回落「暂时没有查找到您的云房卡，请稍后重试或联系管家。」
4. **中文截断修复**：`mb_substr` 后 msg 完整不再被砍
5. **形态**：非入住日时两条消息（订单信息 + 提示），入住日仍只发房卡
6. `php -l` 全绿；生产回归 `--core` 无新增失败

## 6. 不做

- 不改 OrderQueryWorkflow 的文案（含"如需查看云房卡请前往微信客服发送订单号获取"这句——微信客服场景下略冗余，但口径1 要求保持现有结构，不动）
- 不做"提前生成房卡"的申请/预约功能
- 不把房卡话术做成后台可配置（口径3 = 透传中台，不需要本地维护）
