# 商用AI客服系统 V2 改造蓝图

> 基于 V1 MVP 线上实测反馈，问题驱动迭代

---

## 一、V1 遗留问题清单

| # | 问题 | 影响 |
|---|------|------|
| 1 | 管理后台没有正式登录页面，用 prompt() 弹窗 | 体验差，token 容易失效 |
| 2 | HTML 页面直接暴露在公网，没有登录守卫 | 任何人都能访问后台页面 |
| 3 | 没有管理后台首页/仪表盘 | 管理员不知道从哪进 |
| 4 | 没有管理后台退出按钮 | 无法切换账号 |
| 5 | 聊天页面 UI 简陋（默认浏览器风格） | 给客户看不够专业 |
| 6 | 发送验证码没有短信通道，只有 mock | 正式商用要接阿里云 |
| 7 | 代码配置硬编码在 config.php 里 | 不安全，改配置要改代码 |
| 8 | 没有 deploy.sh 部署脚本 | 新客户上线要手动操作 |
| 9 | 没有企业对接 API 文档 | 客户不知道怎么写接口 |

---

## 二、V2 核心改造项（按优先级排列）

### P0：必须先做的

#### 1. 管理后台正式登录页

```
新的管理后台入口：
    http://xx/admin/login.html     ← 登录页（独立页面）
    http://xx/admin/dashboard.html  ← 仪表盘（登录后查看）
    http://xx/admin/persona.html    ← 人设配置（需登录）
    http://xx/admin/knowledge.html  ← 知识库管理（需登录）
```

登录页设计：
- 正式的用户名+密码表单
- 记住登录状态（localStorage token）
- 登录失败有提示
- 有退出按钮

#### 2. 前端登录守卫

所有 `admin/*.html` 页面在加载时自动检查 token：
- 无 token → 跳转到 `login.html`
- token 过期 → 跳转到 `login.html`
- token 有效 → 正常显示

#### 3. JS SDK 管理（复制代码嵌入）

管理后台新增「接入设置」页面，直接显示要粘贴的 JS 代码：

```
接入设置 → 复制以下代码，粘贴到您的网站底部：

<script src="http://xx/sdk/chat-widget.js"></script>
<script>ChatWidgetConfig = { serverUrl: 'http://xx' };</script>
```

### P1：核心体验优化

#### 4. 聊天页面 UI 升级

从现在的"微信风格"改成更专业的客服风格：
- 顶部导航栏显示品牌名
- 聊天气泡更精致
- 添加「转人工」按钮（可以先不支持功能，先显示）
- 添加「常见问题」快捷按钮

#### 5. 配置从硬编码改为读取数据库

`platform_config` 表存所有配置：
- `ai.api_key` → API 密钥
- `ai.model` → 模型名
- `ai.api_url` → API 地址
- `sms.type` → 短信通道（mock / aliyun）
- `site.name` → 站点名称
- `site.logo` → 站点 Logo

config.php 从数据库读取，不再硬编码。

#### 6. 对话记录查看

管理后台新增「对话记录」页面：
- 按时间倒序展示所有对话
- 显示 session_id、时间、消息条数
- 点击查看详情（完整对话内容）
- 搜索功能

### P2：商用准备

#### 7. 企业 API 对接文档

写一份正式的文档页面 `/api-doc.html`，告诉客户：
- 需要实现什么接口
- 请求格式是什么
- 返回格式是什么
- 代码示例（PHP/Python/Node.js）

#### 8. deploy.sh 部署脚本

写一键部署脚本，新客户上线时：
1. SSH 到 VPS
2. 跑这个脚本
3. 自动拉代码、建数据库、配 nginx

#### 9. 知识库批量导入

- Excel 导入问答对
- 下载导入模板

## 三、V2 技术方案

### 前端

| 文件 | 操作 |
|------|------|
| `admin/login.html` | **新增** 正式登录页 |
| `admin/dashboard.html` | **新增** 仪表盘 |
| `admin/auth-guard.js` | **新增** 登录守卫脚本（所有 admin 页面引用） |
| `chat.html` | **改版** UI 美化 |
| `admin/persona.html` | **改造** 接入守卫脚本 |
| `admin/knowledge.html` | **改造** 接入守卫脚本 + 对话记录 |

### 后端

| 文件 | 操作 |
|------|------|
| `api/config.php` | **改造** 从 platform_config 读取配置 |
| `api/admin.php` | **新增** 管理后台 API（统计数据/对话记录） |

---

## 四、实施顺序

```
第 1 轮：正式登录页 + 守卫脚本           ← 先解决"进不去后台"的问题
第 2 轮：仪表盘 + 接入设置页面           ← 让后台有价值
第 3 轮：聊天页 UI 美化                 ← 给客户看要体面
第 4 轮：对话记录查看 + API 对接文档     ← 商用必备
第 5 轮：deploy.sh + 知识库批量导入      ← 提效
```
