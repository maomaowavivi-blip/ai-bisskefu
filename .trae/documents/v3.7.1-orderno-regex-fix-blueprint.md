## 一、问题

**线上实测**(2026-08-14 12:33):客户发"123456789"(9 位数字订单号),v3.7 没生效,仍走原 OrderQueryWorkflow 兜底话术。

**根因**(代码定位):
- `api/wecom_kf.php` 第 296 行:
  ```php
  if (preg_match('/^\d{10,30}$/', $trimmedMsg) && is_dir(__DIR__ . '/wecom_kf_roomcard_v37.php'))
  ```
- 正则要求 **10-30 位**纯数字 — `123456789` 只有 9 位,**不匹配**
- 复制自 `SidecarIntent::looksLikeOrderNo` 的正则,但**该正则是给 KB 检索用的,过严**

**生产日志证据**:
```
[12:33:59] Replied to ... : 订单查询功能暂未上线,请拨打 400-155-9959 联系管家
[12:37:42] Replied to ... : 订单查询功能暂未上线,请拨打 400-155-9959 联系管家
```

两个时间点客户发订单号,**都走了兜底,没有 v3.7 kf link 日志**。

---

## 二、修复方案

### 修改:`api/wecom_kf.php` 第 296 行正则

**改前**:
```php
if (preg_match('/^\d{10,30}$/', $trimmedMsg) && is_dir(__DIR__ . '/wecom_kf_roomcard_v37.php')) {
```

**改后**:
```php
// v3.7.1: 阈值降到 8 位,覆盖美团渠道订单号(19位)和其他可能的 9-10 位订单号
if (preg_match('/^\d{8,30}$/', $trimmedMsg) && is_dir(__DIR__ . '/wecom_kf_roomcard_v37.php')) {
```

**说明**:
- 8 位是经验值:订单号至少 8 位(美团 19 位、OTA 渠道订单号常见 8-15 位)
- 30 位上限防误匹配(手机号 11 位不命中,身份证 18 位也不会匹配 - 因为还有前缀字符)
- 之前 `looksLikeOrderNo` 的阈值不动,只改 wecom_kf 内的正则
