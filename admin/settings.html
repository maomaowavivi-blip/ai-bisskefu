📋 统一网关对接规范

企业需实现一个统一的 POST 接口，通过 action 字段区分不同查询类型。 

POST {网关地址}
Content-Type: application/json
Authorization: Bearer {密钥}

请求体格式：
{
  "action": "query_order | query_room",
  "params": { ... },
  "timestamp": 当前Unix时间戳
}

┌── 订单查询 ──────────────────────────┐
│ action: "query_order"                │
│ params: { "order_no": "订单号" }      │
│                                      │
│ 响应:                                │
│ {                                    │
│   "code": 200,                       │
│   "data": [                          │
│     {                                │
│       "order_info": {                │
│         "room": "房间号/房型",        │
│         "check_in": "入住日期",       │
│         "check_out": "离店日期",      │
│         "order_no": "订单号"          │
│       },                             │
│       "yunfangka_url": "链接(可选)",  │
│       "yunfangka_image": "图片URL"    │
│     }                                │
│   ]                                  │
│ }                                    │
└──────────────────────────────────────┘

┌── 房间查询 ──────────────────────────┐
│ action: "query_room"                 │
│ params: {                            │
│   "room_id": "朝阳店101",            │
│   "question": "空调怎么开"            │
│ }                                    │
│                                      │
│ 响应:                                │
│ {                                    │
│   "code": 200,                       │
│   "data": {                          │
│     "reply": "文字回答...",          │
│     "images": [                      │
│       {                              │
│         "url": "图片地址",            │
│         "title": "图片说明",          │
│         "link_url": "点击链接"        │
│       }                              │
│     ]                                │
│   }                                  │
│ }                                    │
└──────────────────────────────────────┘

失败响应格式（均适用）：
{
  "code": 404,
  "msg": "错误提示信息"
}

注意：API 密钥可包含 "Bearer " 前缀或不含，系统会自动适配。
