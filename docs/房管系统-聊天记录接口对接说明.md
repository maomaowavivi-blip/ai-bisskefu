# 房管系统对接说明：AI 客服聊天记录查询

> 版本 v1.0 ｜ 2026-11-19 ｜ 提供方：柚光 AI 客服系统

---

## 一、一句话说清需求

在房管系统加一个「昨日AI聊天」入口：房管点开 → 列出**他名下房源在指定日期有过 AI 对话的客人** → 点某条 → 展示该客人当天的完整聊天记录。

**页面由你们做，我们只提供数据接口。** 订单与房源、房管的归属关系你们那边本来就有，直接用。

---

## 二、接口

### 基本信息

| 项 | 值 |
|---|---|
| 地址 | `https://43.138.217.6/api/openapi_room_chats.php` |
| 方法 | `POST` |
| Content-Type | `application/json` |
| 鉴权 | Header `X-API-Key: {密钥}`（也支持 `Authorization: Bearer {密钥}`） |
| 频率 | 无硬限制，实际是房管点击频率（每天个位数） |

### 请求

```json
{
  "order_nos": ["5044043418264731373", "1234567890123456"],
  "date": "2026-11-18"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `order_nos` | 是 | 数组，1–200 个订单号。**必须与客人在聊天里报的订单号完全一致**（见第五节第 1 条） |
| `date` | 否 | 查询日期 `YYYY-MM-DD`。**不传默认查昨天**（按服务器当天算） |

### 响应

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "date": "2026-11-18",
    "list": [
      {
        "order_no": "5044043418264731373",
        "room_no": "1703225",
        "session_id": "wecom_kf_af50d62bef57a1d6",
        "channel": "wechat_kf",
        "message_count": 4,
        "first_time": "2026-11-18 23:26:34",
        "last_time": "2026-11-18 23:27:56",
        "truncated": false,
        "messages": [
          {"role": "user", "content": "5044043418264731373", "created_at": "2026-11-18 23:26:34"},
          {"role": "assistant", "content": "订单查询成功：\n房型：暖光归寓丨大床房...", "created_at": "2026-11-18 23:27:56"}
        ]
      }
    ]
  }
}
```

### 字段说明

| 字段 | 说明 |
|---|---|
| `list` | **只含有聊天的对话**。某订单没聊过天就不在列表里，你们那边不用再过滤 |
| `order_no` | 订单号，与请求一一对应 |
| `room_no` | 房号（一单多房时逗号分隔，如 `"10002,10003"`）。可能为空字符串 |
| `session_id` | 会话标识，一般用不上 |
| `channel` | `wechat_kf`（微信客服）/ `web`（小程序 H5）/ `api`（第三方接入） |
| `message_count` | 本次返回的消息条数 |
| `first_time` / `last_time` | 该对话首条 / 末条消息时间 |
| `truncated` | `true` 表示消息超过 500 条已截断（只返回最早 500 条） |
| `messages[]` | 消息流，按时间正序。`role` 为 `user`（客人）或 `assistant`（AI） |

### 错误返回

| HTTP | code | 场景 |
|---|---|---|
| 401 | 401 | 没带 key |
| 403 | 403 | key 不对或被禁用 |
| 400 | 400 | `order_nos` 缺失/超 200 项/含非法字符，或 `date` 格式不对 |
| 405 | 405 | 用了 GET |
| 200 | 0 | 正常（**`list` 为空数组也是正常**，表示这些订单昨天没人问过 AI） |

## 三、你们那边怎么接

1. 房管点「昨日AI聊天」
2. 你们算出「该房管昨天名下房源对应的订单号列表」→ 作为 `order_nos` 传入（**归属计算在你们那边，我们不做**）
3. 拿返回的 `list` 渲染列表：订单号 / 房号 / 时间段 / 消息条数
4. 房管点某一条 → 直接渲染 `messages`，**不用再发请求**

一次调用返回列表和完整消息流，不需要分页或二次请求。

## 四、curl 自测样例

```bash
curl -X POST 'https://43.138.217.6/api/openapi_room_chats.php' \
  -H 'X-API-Key: {密钥}' \
  -H 'Content-Type: application/json' \
  -d '{"order_nos":["5044043418264731373"],"date":"2026-11-18"}'
```

密钥请私下提供，不要写进公开文档或代码仓库。

---

## 五、三个必须注意的点

1. **订单号必须同构**：我们这边绑定的是客人报给 AI 的渠道订单号（携程/美团等）。如果你们 PMS 里存的是内部单号，需要先做一次映射，否则查不到任何记录。**这是联调第一步要确认的。**
2. **客人姓名/联系方式我们不提供**：聊天记录里没有这些字段，你们按订单号从自己系统补齐。
3. **只覆盖报过订单号的对话**：客人如果只问「几点入住」而全程没提订单号，无法归属到订单，这类记录不在视图里。

---

## 六、联调建议

- 先拿 **1 个真实订单号 + 明确有聊天的日期** 单测，确认能返回消息流，再跑批量
- 日期不传会默认取昨天；若发现返回为空但你知道那天有对话，优先检查订单号是否同构
- 有问题直接找我们，附上返回的完整 JSON
